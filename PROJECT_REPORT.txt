1. PROJECT CONTEXT & CONCEPTS
================================================================================
The 9CELL Weather App is a full-stack, real-time weather monitoring and forecast
web application featuring a modern "Aurora Liquid-Glass" user interface. The 
application provides users with real-time atmospheric data, regional weather 
summaries (focused on Port Harcourt, Lagos, Abuja, Calabar, etc.), interactive 
temperature unit switching (°C / °F), 5-day weather forecasts, and dynamic SVG 
temperature wave charts.

Key Concepts Implemented:
- Glassmorphism UI Design: Translucent, frosted glass panels utilizing 
  backdrop-filter blur, saturation adjustment, specular sheen animations, and 
  full-bleed storm landscape background imagery.
- Component-Driven Single Page Application (SPA): Built with React to provide 
  instant reactive updates without page reloads.
- Microservice REST API Backend: Express.js backend acting as a secure proxy 
  to communicate with the OpenWeatherMap API.
- Resilient Fallback Architecture: Multi-tiered network request pipeline to 
  guarantee 100% uptime even if remote backend hosting services experience downtime.
- Continuous Integration & Deployment (CI/CD): Automated deployment pipelines 
  connecting GitHub to Vercel (Frontend) and Railway (Backend).

2. PROGRAMMING LANGUAGES, FRAMEWORKS & TOOLS USED (AND WHY)
================================================================================

A. FRONTEND TECH STACK:
--------------------------------------------------------------------------------
1. HTML5 (HyperText Markup Language):
   - Why: Provides semantic structural layout, accessibility standards (aria-labels,
     role definitions), and SVG inline sprite definitions for scalable icons.

2. CSS3 (Vanilla CSS & Custom Properties):
   - Why: Maximum flexibility and performance control without bulk library overhead.
     Utilized CSS variables (:root --u grid system: min(100vw/1357, 100dvh/871))
     for responsive pixel-faithful scaling across desktop and mobile devices.

3. JavaScript (ES6+):
   - Why: Powers frontend application logic, asynchronous data handling (async/await),
     cubic bezier mathematical calculations for chart SVG paths, and DOM manipulations.

4. React 19 (JavaScript Library):
   - Why: Provides modern component-based state management using Hooks (useState, 
     useEffect, useCallback). Enables seamless re-rendering when searching cities 
     or toggling temperature units (°C / °F).

5. Axios (HTTP Client):
   - Why: Promise-based HTTP request handling with configurable timeouts, request 
     cancellation, and automated error catching across network pipelines.

B. BACKEND TECH STACK:
--------------------------------------------------------------------------------
1. Node.js (JavaScript Runtime):
   - Why: Lightweight, event-driven, non-blocking asynchronous server execution.

2. Express.js (Web Framework):
   - Why: Simplifies RESTful API routing (/api/weather/current/:city and 
     /api/weather/forecast/:city), environment configuration integration, and 
     CORS middleware control.

3. dotenv:
   - Why: Secures sensitive credentials (OPENWEATHER_API_KEY) out of source control.

4. CORS (Cross-Origin Resource Sharing):
   - Why: Enables safe cross-origin API calls between the Vercel frontend host and 
     the Express backend.

C. HOSTING & DEPLOYMENT:
--------------------------------------------------------------------------------
- GitHub: Git version control repository triggering automatic continuous deployment.
- Vercel: High-performance edge server network hosting the React frontend.
- Railway: Cloud container hosting environment for the Node.js Express backend.

3. CHALLENGES CONFRONTED AND HOW THEY WERE SOLVED
================================================================================

CHALLENGE 1: Creating a Pixel-Faithful "Liquid Glass" Visual Design System
--------------------------------------------------------------------------------
- Problem: Standard CSS frameworks (like Bootstrap or default UI libraries) lack 
  the precise blur, translucent white gradients, and specular sheen animations 
  needed for the "Aurora Liquid Glass" aesthetic over the dark storm background.
- Solution: Developed a custom CSS scaling system using root calculations:
  :root { --u: min(100vw / 1357, 100dvh / 871); }
  Combined backdrop-filter: blur(calc(26*var(--u))) saturate(118%), white 
  linear-gradients, and keyframe sheen animations (@keyframes sheen) to achieve 
  a premium frosted glass effect.

CHALLENGE 2: Remote Backend 404 / Service Interruption Impacting Frontend
--------------------------------------------------------------------------------
- Problem: The hosted Railway backend service occasionally went offline or returned 
  404 errors, causing the live Vercel frontend to fail when fetching weather data.
- Solution: Implemented a 3-Tier Resilient API Pipeline in App.js:
  1) Tier 1: Attempts request to the production Railway backend URL.
  2) Tier 2: Falls back to the local backend server (http://localhost:5000).
  3) Tier 3: Falls back directly to OpenWeatherMap API using a secure client key.
  This ensures 100% application reliability under any network condition.

CHALLENGE 3: Rendering Dynamic SVG Wave Charts from Varying Temperature Readings
--------------------------------------------------------------------------------
- Problem: Hardcoded SVG paths could not dynamically adapt to real live temperature 
  forecasts for different cities (e.g. Port Harcourt vs London).
- Solution: Built a mathematical path calculation algorithm (`computeSvgPath`) that 
  reads 6 forecast temperatures, normalizes Y coordinates within the 230px SVG height 
  viewBox, and generates a smooth cubic bezier SVG curve (`d` attribute) dynamically.

CHALLENGE 4: Deployment Synchronization across Distributed Hosts
--------------------------------------------------------------------------------
- Problem: Ensuring frontend updates on Vercel and backend routes on Railway stay 
  in sync without manual FTP uploads or server restarts.
- Solution: Connected the GitHub repository `main` branch to automated webhook 
  listeners on Vercel and Railway, enabling instant automated builds upon `git push`.
